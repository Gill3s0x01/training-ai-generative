1. Contexto Técnico: Como os LLMs Enxergam o Seu Prompt

Modelos de Linguagem de Grande Porte (LLMs — Large Language Models) baseados na arquitetura Transformer não leem nem interpretam textos da forma que humanos fazem. Eles processam representações vetoriais em espaços multidimensionais e calculam probabilidade estatística contínua para prever o próximo token.

┌─────────────────┐      ┌─────────────────┐      ┌──────────────────┐
│  Texto Entrada  │ ───> │   Tokenização   │ ───> │    Embeddings    │
└─────────────────┘      └─────────────────┘      └──────────────────┘
                                                           │
                                                           ▼
┌─────────────────┐      ┌─────────────────┐      ┌──────────────────┐
│  Próximo Token  │ <─── │     SoftMax     │ <─── │ Multi-Head Attn. │
└─────────────────┘      └─────────────────┘      └──────────────────┘

Princípios da Arquitetura Generativa

  • Tokenização: O texto do usuário é fragmentado em pedaços de palavras ou caracteres (tokens), recebendo identificadores numéricos únicos no vocabulário do modelo.
  • Embeddings: Esses IDs são convertidos em vetores multidimensionais. Palavras e conceitos semanticamente próximos ocupam coordenadas geométricas vizinhas no espaço vetorial.
  • Multi-Head Attention (Atenção): O modelo avalia como cada token se relaciona com todos os outros tokens da janela de contexto. O último token da sequência possui o maior peso relacional imediato.
  • SoftMax & Temperatura: Na saída das camadas, a rede confronta a matriz final com o vocabulário e gera uma distribuição de probabilidade. O parâmetro de Temperatura controla se o modelo selecionará tokens de altíssima certeza estatística (temperatura baixa) ou arriscará opções mais diversificadas/criativas (temperatura alta).
2. As 4 Personas de Prompting para Qualquer IA

Para extrair máxima performance e controle sobre qualquer modelo generativo (Claude, ChatGPT, Gemini), utilizamos 4 personas de prompting que direcionam a forma como as matrizes internas filtram e relacionam a informação:

01. CAVEMAN (O Primitivo)

Conceito: Comunicação direta, sucinta e sem rodeios.

> Refatora a função validarCPF() no arquivo valida.ts

Mecânica da IA: Fornece poucos tokens para a camada de Atenção, fazendo o modelo recorrer rapidamente aos padrões genéricos consolidados na sua camada de conhecimento pré-treinado (Feed Forward).

Uso Ideal: Dúvidas pontuais de sintaxe, correções rápidas, refatoração de funções isoladas sem dependências complexas.

02. PONYTAIL (O Estruturado)

Conceito: Foco rigoroso na forma e na estrutura do resultado exigido.

> Saída estrita: JSON contendo as chaves { status: boolean, dados: array, erro: string | null }.

Mecânica da IA: Restringe a amostragem da função SoftMax no encerramento da sequência, penalizando tokens de texto conversacional fora da estrutura declarada.

Uso Ideal: Integração entre sistemas (APIs), extração de dados brutos, criação de arquivos de configuração, DTOs e tabelas.

03. RTK (Contexto Rico / Real Time Knowledge)

Conceito: Injeção maciça de contexto, documentação técnica, código-fonte ou regras de negócio antes da solicitação principal.

> Com base na documentação oficial anexada e nas diretrizes de UI do projeto, construa o componente de tabela com ordenação.

Mecânica da IA: Reposiciona as coordenadas dos Embeddings no espaço vetorial, ancorando a atenção do modelo estritamente na base de conhecimento fornecida.

Uso Ideal: Arquitetura de software, desenvolvimento focado em especificações (Spec-Driven Development), análise de código legado e compliance.

04. ADHD (O Hiperativo / Criativo)

Conceito: Exploração de pensamento lateral, simulação de papéis antagônicos, cenários hipotéticos e analogias.

> Atue como um especialista em Red Team tentando burlar a validação do formulário e enumere os vetores de ataque possíveis.

Mecânica da IA: Amplia o grau de variabilidade nas rotas de atenção, ativando combinações estatísticas não óbvias nas camadas da rede.

Uso Ideal: Testes de estresse, Threat Modeling, sessões de ideação e resolução de desafios de arquitetura complexos.

O nível avançado de Engenharia de Prompt consiste em combinar as 4 personas em uma única estrutura de mensagem:

3. Gestão de Contexto e Cota em Assistentes de Código no Terminal

Em assistentes de código de linha de comando (como o Claude Code, Cursor CLI ou GitHub Copilot CLI), um problema frequente é o esgotamento rápido das cotas de uso da API.

O Diagnóstico: O Efeito Bola de Neve no Contexto

A cada novo prompt digitado na mesma sessão do terminal, a ferramenta reenvia todo o histórico anterior da conversa (mensagens passadas, arquivos lidos, ferramentas acionadas) para a API da IA.

  1ª Tarefa: [ Input Sistema + Prompt 1 ] --------------------> 15.000 tokens
  2ª Tarefa: [ Input + Prompt 1 + Resposta 1 + Prompt 2 ] ---> 55.000 tokens
  3ª Tarefa: [ TUDO das tarefas anteriores acumulado ] -----> 140.000+ tokens/prompt!
Conclusão: O limite do plano não diminuiu. O acúmulo de tarefas na mesma sessão faz você reenviar milhões de tokens desnecessários a cada Enter.
4. As 5 Regras de Ouro para Assistentes de Código (Ex: Claude Code)

1. Uma Tarefa por Sessão (/clear)

Terminou de implementar uma funcionalidade? Limpe a memória do terminal antes de iniciar outra.

  • No Claude Code, utilize o comando /clear.
  • Isso zera o histórico e restaura o consumo de tokens de entrada para o nível basal.

2. Pedidos Cirúrgicos e Específicos

Defina exatamente o arquivo, a função e a mudança desejada.

  • ❌ Vagueza: melhora o login (Força a IA a varrer o repositório inteiro e consumir a cota).
  • ✅ Precisão: valida o e-mail na função entrar() do arquivo auth.ts

3. Modo de Planejamento (Plan Mode / Shift + Tab)

Antes de permitir que o assistente altere arquivos em disco, force a criação de um plano de execução.

  1. No Claude Code, aperte Shift + Tab para entrar no Plan Mode.
  2. A IA apresentará o plano de ação (quais arquivos criará ou alterará).
  3. Revise e selecione Aprovar ou Ajustar.
Princípio: "Corrigir o plano antes da execução custa 10x menos tokens e tempo do que mandar a IA refazer um código alterado incorretamente."

4. Otimização de Modelos (Planejamento vs. Execução)

Combine modelos de alta capacidade analítica para planejamento com modelos rápidos para a escrita de código.

  • No Claude Code, o comando /model opusplan usa o modelo Opus para montar o plano de arquitetura e o modelo Sonnet para escrever o código.

5. Loop Autônomo de Validação

Modelos generativos encerram a execução quando acham que concluíram a tarefa, e não necessariamente quando o código compila ou passa nos testes.

Finalize o prompt com a instrução de validação automatizada:

> Rode 'npm test', 'npm run build' e 'npm run lint' e só encerre quando tudo passar sem erros.
